### C3R-1：错误出口统一（PF-1）

- 根 `opendir` 被拒绝、扫描期间根消失/被替换，不得吞错返回 `complete=true / no-migration-needed`。根级错误可以结构化拒绝；若返回报告，必须明确不完整和错误码。
- 可选目录不存在是正常未使用；非根目录 `stat` / 打开失败是问题，不等价于不存在。按受控类别/路径收集，预算允许时继续检查后续类别。
- IO 取消必须继续结构化抛出，不能被通用错误分支收集成普通问题。未知异常不能透传原始错误正文或客户信息。
- 用既有 hooks 确定性覆盖根列举 EACCES、非根探测/打开失败、根候选并发消失与取消对照；不依赖真实 ACL 竞速，不额外安装依赖。
- 不放松根内路径、链接与 paired cleanup，也不改变 Boundary 的既有写入语义。

### C3R-2：共同问题额度（PF-2）

- `problems.length + manual.length <= maxProblems`；两类明细共享一份额度，与处理顺序无关。
- 明细裁剪后，独立阻断/人工总计仍正确，不把已知阻断当成通过；丢弃统计和 `truncatedBy` 保持解释一致。
- 永久测试至少包含：坏记录与锁混合；问题先到/人工事项先到；额度 0、1、恰好够和差一；只含单类的对照。

### C3R-3：真实输出字节（PF-3）

- 给摘要、问题、人工事项定义一个唯一可复现的序列化计量口径，计入数组括号和分隔符；字段注释/limits/实施记录一致。
- 若固定报告信封不在 `maxOutputBytes` 内，明确说明。额度小于空载荷最低开销（含 0）时，必须返回空明细/incomplete，并明确最低信封开销是否作为例外如实计量，或显式省略该载荷；不得声称完整、不得在非空明细上漏算。
- 增量计量可以使用明确的序列化包络，避免每次全量重算导致不必要的平方成本；不能按字符数代替 UTF-8 字节。
- 测试使用 `Buffer.byteLength(JSON.stringify(...), "utf8")` 独立计算规范化明细包络。覆盖空/单/多条、中文、JSON 转义和人工事项；触顶不误报完整，`outputBytes` 不低报。

### C3R-4：截断统计真实（PF-4）

- 将 `listing.scanned` 的真实观察成本带回总统计，包括截断分支；明确唯一的超限探测条目是否计入。不要把未处理候选误报为成功读取。

- 测试覆盖只有根列举触顶、第一层目录触顶、多目录累计触顶、0/1 边界与无截断对照；统计与真实观察次数一致，耗尽后不继续新 IO。
- `maxFileBytes=0` 等既有零值语义也需核对注释与结果，不能保留与实现相反的描述。

### 环境证据修正（不新增功能）
