## 1. 本轮目标

关闭 S1～S5，给 BM-02B 一个可依赖的读取/初始化基础。只修改已存在 storage/contracts、必要测试及文档，不新增 UI、模型写工具、RAG、厂商适配或 Pi 内核改造。

分为三个小任务顺序实施，各自先加失败回归再修复：

| 子任务 | 范围 | 完成标准 |
|---|---|---|
| AR-1 | S1：初始化完整发布 | 不支持硬链接/权限失败明确拒绝或安全发布；不存在目标不能留下空/半 registry |
| AR-2 | S2/S3：完整校验与读取消 | 单条与列表校验一致；增长不解析前缀；最后 IO 点取消为整体 cancelled |
| AR-3 | S4/S5：列表预算与绑定解析 | 单条异常不拖垮列表；异常输出也有限额；不忽略身份矛盾或任取工作区 |

不扩大成 BM-02B；S1 可先采用“不支持就明确失败”的保守方案，无需为了回退另造完整跨进程事务。

## 2. 具体开发要求

### AR-1：初始化

- 消除直接向最终目标 wx 写完整 payload 的回退。保留同目录完整临时文件的非覆盖发布；如平台不支持，提供结构化失败及说明，不创建半目标。
- 既有文件合法则 existing，损坏/未来版本则对应错误；不覆盖、不重置 revision，不吞权限问题。
- 初始化的竞争重试只针对真正可重试的竞争；cancelled、权限、永久结构/版本错误不得一律变成 init-race。
- 写失败/取消/重试的临时文件生命周期明确；不实现启动自动删锁/自动清空 registry。
- 测试强制 ENOSYS/权限失败分支；读取者在发布窗口只能看到缺失、明确竞争或完整合法内容，不能看到空/半最终文件。补真实两子进程竞争和故障窗口测试。

### AR-2：读取与共同校验

- 提取共享校验链：版本 → kind schema → 文件 ID/记录 ID → task.projectId 或 context.targetProjectId。列表与 readRecord 复用它。
- 用类型化 kind→record 映射传递结果，避免新增 any、as never 或多重盲 cast。公共生产接口校验非法 kind/ID，不出现裸 TypeError。
- 有界读取到 EOF 或最大允许字节+1；可用分块缓冲，不需要按上限一次性分配。stat 是快速预检，不是最终数据长度。
- 读取期间增长超过预算拒绝；未到 EOF 不解析“恰好合法的前缀”。所有 FileHandle 在成功、取消、解析错误、超限时都关闭。
- signal 在最后 read/迭代结束/返回之前都检查。WithBoundary 入口显式给出的 signal 与 boundary signal 的优先关系必须真正生效，不能只做入口检查。
- 列表和初始化重试 catch 不吞取消。发布后的取消结果按实际已提交状态描述，不假装回滚已提交文件。
- 错误 detail/cause 对外不带 JSON 原文、客户标识或正文片段；保持内部诊断与对外摘要的边界。

### AR-3：列表与绑定

- 候选文件名、ID、路径派生、读取、版本、结构、归属错误都可进入有界 problems；坏一条不导致整个列表崩溃，越界/权限/整体取消则按明确政策失败。
- 条目字节计数涵盖实际输出字段；为 problems 设有限数量/字节，超限返回截断原因和 droppedProblems（或等价计数）。固定头和 payload 的预算语义写清；不要把没返回的问题说成没有问题。
- 链接/非记录项的跳过策略明确，无法完整读取时要有可解释状态；不为了列问题而读取链接目标正文。
- 所有可配置限额均为合法有限整数，undefined 保留默认，不合法输入结构化拒绝；默认对象不允许被一次调用修改并影响后续调用。
- registry.projects 的 biosProjectId 唯一；既有 workspaceId/路径/desktopProjectId 唯一性仍保留。
- 查询条件同时提供时必须一致；路径属于 A、显式项目为 B 不允许返回 A resolved。
- 多工作区仅指定项目/桌面 ID 时返回项目级命中或显式需要选择/歧义；不返回数组首个作为已确定工作区。单工作区仍可自动解析。
- registry 仅做身份绑定，不复制分支/HEAD；不隐式合并同远端目录或删除离线绑定。

## 3. 必须补的永久回归

1. 强制硬链接不支持/权限失败/发布暂停；不存在的最终 registry 不暴露空/半内容，既有数据原 hash 不变。
2. A 目录内放 B 任务/上下文清单：readRecord 拒绝；列表为问题条目，不返回摘要。
3. stat 后文件从短合法 JSON 增长：超限/变化得到明确错误，不接受合法前缀；测试真实达到 EOF 的正常读取。
4. 最后 read EOF 时取消、空目录打开期间取消、列表最后一条取消、初始化竞争等待时取消：整体 cancelled，不成功/不进入 problems/init-race；关闭资源。
5. 合法文件混入大写/非法 ID 文件名、坏项目目录名、损坏记录：其余记录继续可列，异常明确。
6. 小字节预算 + 多条损坏记录：问题输出也受限，截断原因/丢弃计数可见；NaN/Infinity/负数/非整数/undefined 的限额行为明确。
7. 两工作区同一项目的项目级查询、矛盾组合查询、重复 biosProjectId：不任意选择、不通过重复绑定。
8. 初始化时目录 junction 逃逸与最终文件链接边界；不能创建文件链接时保留显式未测并在有权限的平台补测，不降断言。
9. 非空 fixture 新进程读取：项目/工作区 ID、记录 ID 和 revision 一致，而非只读空 registry 头；不需要模型或真实 BIOS 项目。

用自建临时数据和受控 IO 故障注入；测试时序明确且有超时，不靠碰运气。错误注入是复现特殊分支的方法，不能将其写成“真实磁盘已发生过”。真实子进程要带 error/超时/输出上限/清理。

## 5. 收尾通过后的下一阶段：BM-02B

届时只开发 core 的写入协议，不立即给模型开放写知识工具：

- 显式 create 与 update 分开；update 必须 expectedRevision，冲突返回实际 revision，不自动重放。
- 同一记录跨进程互斥，可取消等待、有超时与可解释锁归属；不按 PID/时间猜测自动删未知锁。
- 在锁内重新读取/校验/比较 revision，再准备同目录临时完整文件、原子替换；所有合法写入递增一次 revision。
- 真正两子进程从同一 revision 更新：最多一个成功，另一方冲突，不能丢更新；读者只见完整旧/新记录。
- 坏 JSON/未来版本/超限/链接拒绝写入，原文件 hash 不变；失败不把原件移走后留下空洞。
- 先实现单记录更新；项目档案与 registry 双文件绑定原子性、journal/崩溃恢复留 BM-02C，不能假装两个 writeFile 是事务。

这一节是路线说明，不是授权当前 AI 同时实施 BM-02B。BM-02AR 复验通过后再确定详细接口/故障门禁。
