## 3. 节点 B：M1 纯记忆策略，实际代码交付

完整读 [分层记忆与时态设计](layered_memory_temporal_design.md)；补读 `core/contracts/common.ts`、`records.ts`、现有校验/版本/ID 规则。建议在 `core/memory/` 按契约、v1 投影、策略和窄出口拆分；API 名由实现确定并记入实施记录，不假称已存在。

输入是**已经取得的记录与调用方提供的明确策略/快照**，不是目录或 Session。模块不得 import fs、扫描 Git、连模型、读取时钟或写库；查询时间由输入传入。复用现有严格记录类型/校验，新增的时间/关系/范围只是有明确来源的内存决策视图，不能冒充 schema v2 已落盘。

### 3.1 必需输入与输出语义

- 目标上下文：project/workspace/customer 等强身份与实际快照，可 unknown；不用厂商名、板名或相同远端推断同一项目。
- 候选依据：recordId/revision、已读取权威性/来源指纹、确认或审核状态、明确适用范围、证据/验证可用性；纯模块不能把调用方的读取声明当自己已完成磁盘复核。
- 可选时态视图：发生/录入/生效信息分开，明确状态、被替代/撤回目标版本和范围；缺失保持 unspecified，不从 updatedAt 构造。
- 读取意图 current/history；授权与模型端点策略显式 allow/deny/unknown，由上层提供。现有 authorization 文本是声明，不是企业认证或可信权限服务。
- 输出区分当前可用依据、仅供参考、需复核/冲突、显式历史及排除；返回固定原因码、可见来源 ID/revision 与适用性依据。事实有效性和验证强度分别报告，不揉成一个置信度。

未授权候选不得通过标题、正文、ID 或排除计数泄漏；history 同样不能绕授权。权威来源不可读、预算不足、状态未确定时显式 unresolved/incomplete，不能回退缓存并宣称有效。输入超限给通用有界错误，不回显被拒材料。

### 3.2 本批一次完成的策略

1. **v1 兼容投影**：严格校验现有记录后只在内存添加 legacy/unspecified；不 mutate 输入、不新增落盘字段。已审核且匹配授权范围的旧经验可作为参考；deprecated 不进入 current 推荐；无快照不得称当前硬件验证通过。
2. **确认与候选冲突**：人工 confirmed 值不被新检测候选覆盖；保留两者，输出需确认差异。没有证据保持 unknown。
3. **范围匹配**：先授权再可见；客户/项目/工作区/板卡/构建目标等已声明约束逐项判定。未指定是否通用由显式契约决定；不知道不自动等于匹配。Board A 的替代不影响 Board B。
4. **时间与因果**：半开生效区间 `[from,to)`；未来未生效、已结束、未知分别处理；录入较晚的旧测试不成为新验证；同记录 revision 因果优先，跨记录没有显式关系就不按时间戳选赢家。
5. **替代/撤回与冲突**：关系必须绑定 ID/目标 revision/范围；缺引用、版本不匹配、循环或未完整读取返回 unresolved。撤回不得因旧摘要复活；history 保留历史标记；范围重叠且值冲突时不自动选择 timestamp 最新的一条。
6. **证据与验证漂移**：仅比较明确相关依赖，HEAD/文件 hash/板卡/目标变化时 current 验证需复核；unavailable 不等于删除或判错；编译通过不升级为上板通过。
7. **预算与确定性**：候选、关系、原因数、字符串和输出都有明确限额；先检查形态/数组长度再遍历；0 不当无限制，非法数拒绝。无界关系遍历/递归不允许。相同输入输出一致，不依赖数组顺序裁定真伪；超预算完整性可见。

这是决策模块，不是完整搜索引擎或持久化历史账本。对业务不能由 v1 表达的信息，结果保持未知/参考并在 M2 列出缺口，不能为演示伪造当前验证。

### 3.3 永久测试与演示

将 MT-01～04、09、12 的**纯策略部分**落为永久测试；同时覆盖 MT-05/07/08/10/11 的纯决策对应场景，明确尚未验证真实检索/Session/IO：

- confirmed 与候选冲突；时钟回拨/同毫秒、较高 revision；旧测试后录入与未来规则；区间端点/非法日期。
- 同需求 Board A 替代、Board B 不受影响；跨客户未授权与端点 unknown 无标题/ID/计数泄漏。
- 撤回旧摘要、deprecated 陈旧候选、history 授权；缺关系目标、错误 revision、循环及有界停止。
- HEAD/板卡/构建目标/相关 hash 变化；无关文件变化不全局失效；证据 unavailable；compile 与 board-boot 区分。
- legacy 无生效时间/结构化验证范围，只供参考；权威记录不可读/预算不足不返回无警告事实。
- 输入不变、顺序置换结果语义一致、Unicode 字节预算、0/精确/差一、非法限额；不需要凑固定测试数量。

交付一个纯 Node 合成 PXE 场景演示：目标 Board B、新需求未来生效、旧 Board A 经验、已撤回摘要、未经授权的另一客户资料同时出现，输出可用参考、待确认和排除结果。调用真实 M1 API，不只写预期字符串；不发布客户/IBV 源码，也不新增生产 CLI 命令。
