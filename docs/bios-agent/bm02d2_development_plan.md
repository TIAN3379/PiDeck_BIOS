## 3. D2 API 与目录约定

建议入口 `exportKnowledgeBackup(options)`，通过 `core/storage/backup/index.ts` 的窄出口再导出；最终签名写入实施记录。参数至少明确：

- `root`：显式、完全限定的源知识根；不得自动读取默认真实用户库。
- `backupRoot`：显式、完全限定且尚不存在的目标目录；其父目录必须已存在。不自动创建任意父目录。
- `offlineConfirmed: true`：调用者声明已经关闭使用该知识根的所有写入者；缺失或不是 true 就在任何输出创建前拒绝。
- 可选 `limits: Partial<BackupLimits>`、`preflightLimits: Partial<PreflightLimits>`、`signal: AbortSignal`。backupId 与合法 createdAt 可以在入口生成；需要确定性测试时遵循既有注入风格。

严格校验参数和限额，再发起 IO。沿用 D1 的 `backupVersion=1`、`consistency="offline-copy"` 与 exclusions；不把源路径、机器名、客户名称、正文或预检报告放进 manifest。files/directories 按规范路径稳定排序，不能通过排序去重。

源根使用既有 Boundary 的 canonicalRoot 语义；目标父目录也要核对真实路径。拒绝源与目标相同、目标在源内、目标是源的祖先以及词法分离但解析后重叠的路径。比较以路径段和 canonical 路径为依据，不使用字符串前缀。目标及写入路径段不接受 symlink/junction；首版拒绝目标父链中的链接，声明此限制即可，无需开发“安全跟随链接”。

目标已经存在时一律拒绝，包括空目录、完整旧备份、半成品、文件或链接。不能凭 exists 检查承诺无覆盖：必须用排他创建领取全新目标目录；两进程竞争同一目标时只有一方取得所有权，另一方不得写入或清理赢家内容。

```text
<backupRoot>/
  manifest.json       # 最后发布；其存在是本 API 的完成标记
  data/
    registry.json
    projects/...
    experiences/...
    features/...
    audit/...
    journal/...       # 按实际存在保留
```

必需固定目录和已知空目录按 D1 清单保留。cache/locks 内容不复制，也不在 data 清单里创建；D3 将来负责恢复空目录。

## 4. D2 实现流程与边界

### 4.1 准入与受控 inventory

先调用既有 `inspectKnowledgeStore`。至少要求：`complete=true`、`outcome="no-migration-needed"`、无截断/丢弃诊断、`blockingProblems=0`、`manualItems=0`。不要仅检查报告里的 problems 数组是否为空。

预检 blocked/incomplete、坏 JSON、未来版本、活动/遗留锁、prepared/conflict journal、受控区域 `.tmp` 或未知落点，都不能导出一个宣称正常完整的备份。不得调用 initialize/reconcile、修改记录、抢锁或删除源残留来“帮助通过”。cache 内容是协议明确排除项，不递归检查其正文；排除目录本身仍按既有边界检查。

预检是准入工具，不是完整复制清单或原子快照。另在已知固定深度内获取受控目录/文件 inventory，复用 D1 落点判据和既有有界列举能力；不递归未知子树、不扫 BIOS 源码、不跟随内部链接。列表不得静默截断后继续复制。

不要从可能被裁剪的 summaries 拼出缺文件的备份。两种实现皆可：独立的受控 inventory；或在证明预检明细完整且覆盖所有复制落点的前提下复用它。最终要用真实目录清单测试证明完整性。

### 4.2 原始字节复制与预算

准入通过后排他创建新目标，按受控 inventory 创建目录、复制文件。每个源文件在读取前核对路径/链接与常规文件类型；使用真实句柄有界读取、实际字节计量和 SHA-256，原样写入目标，不 JSON parse/stringify 改写 payload。

- 复用现有路径、取消与错误原语；若 Boundary 需要原始字节读取窄方法，可以有限添加/抽取并跑原读取回归，不能因此重写 Boundary 或改变旧 JSON 行为。
- stat 只是提前拒绝依据，实际读取仍须限定到预算＋一次超限探测，拒绝读取期间增长。源文件复制前后核对可用身份/大小/修改信息，发现变化失败。
- 文件/目录数量、相对路径、单文件/总 payload、manifest 字节和诊断条数沿用 D1 限额；总量在安全整数溢出前拒绝。预检独立使用 PreflightLimits，实施记录列出两者实际生效值；有效可导出范围由较紧预算决定，不默默调成无限。
- 优先逐文件处理并释放缓冲，或按明确的总字节上限处理小库；不把源和目标的全部数据无界累积。各固定阶段分别有界，实际 IO 会因预检/复核多次读取，不把 `maxTotalPayloadBytes` 冒称整个导出过程只读一次的总 IO 预算。
- 文件使用排他创建；写入要处理短写，完成后关闭句柄。payload 在无 manifest 的目标里可能暂时可见，不宣称每个 payload 是独立原子发布。

### 4.3 复核与最后发布

复制结束后，重新完整盘点源目录/文件集合并复跑预检；集合、必要元信息或准入结论变化都失败。再次有界读取源 payload，重算 hash 与复制时清单比对，不能只比较文件名、长度或 mtime。同长度内容变化也必须能发现。

接着有界回读目标 payload，核对唯一集合、实际字节数与 SHA-256；使用 D1 的 manifest 校验和原始字节核验口径。可以逐文件计算 hash，避免为调用纯 API 而无界装载整库，但不能另造一套放宽的 manifest 校验。

全部成功后，才发布经过 D1 校验的规范 manifest：目标内写独占临时文件、sync、close，再用非覆盖发布到 `manifest.json`。可以复用现有完整文件 link 发布方式；不使用“先 exists 再覆盖写”，也不把写了一半的 manifest 当完成标记。硬链接发布不可用时受控失败，不做暴露半文件的回退。

首次 manifest 发布成功是提交点。目录此前可见但属于未完成容器；完成标记不替代 D3 的全部恢复准入。这个方案不需要目录 rename 的跨平台覆盖规则、额外发布服务或新增通用锁协议。

一致性仍是 **offline-copy＋观察式变化检测**。两次检查一致不能证明从未有写入者，也不能发现所有改后恢复原样的变化；不承诺在线原子快照、同机恶意进程沙箱、网络盘或断电耐久性。

### 4.4 失败、取消与清理

返回或抛出的公共失败要有受控类别、阶段和有界诊断；区分输入非法、源准入阻断、预算耗尽、源变化、目标冲突、IO 失败与取消。沿用已有 StorageError 的适用码；确需新增时用 backup 窄契约，不改旧码含义。

- manifest 发布前失败/取消：不能留下 `manifest.json` 完成标记，停止新复制并关闭已打开句柄。
- 只清理本次排他创建且仍可确认归属的文件/目录，目录自深到浅删除。不得递归删除调用者指定路径、源根、目标父目录、别人已有目标或竞争进程产物。
- 若发现未知内容、路径被替换、归属不明或删除失败，停止有风险的清理，保留残留并报告阶段/清理状态。主失败不被清理失败覆盖；残留不能冒充完整备份。
- manifest 已发布成功后的迟到取消/临时清理失败：如实报告 `published=true` 和清理结果，不假称未提交、不回滚已完成备份。受控临时残留可能影响未来恢复准入，明确待人工处理。
- 不透传原始 fs/JSON 异常、cause、客户正文或未知条目名。成功可返回调用者显式指定的目标路径、backupId、文件数/总字节与一致性标记；不附完整源路径或整个预检报告。

| 场景 | 必须证明 |
|---|---|
| D1R 原复现与正常对照 | B1/B2 旧红新绿，已有断言保留，正常子视图/反序/零额度不退化 |
| 最小库、已知空目录、非空库 | 真正生成 manifest/data；预期 inventory 与实际唯一集合完全一致 |
| 业务与工件共存 | 五类记录、普通 journal v1、审核 journal v2、合法意图/事件均不漏；cache/locks 内容不复制 |
| 字节保真 | 合法 JSON 的中文、CRLF/LF、缩进、尾部空白原样保留；用独立 fs/crypto 重算长度/hash，源前后字节与完整清单不变 |
| 准入拒绝 | 坏 JSON、未来版本、锁、prepared/conflict、受控残留/未知条目、预检截断或诊断裁剪，均无完成标记、不修改源 |
| 目标拒绝 | 缺离线确认、相对路径、源目标重叠、链接逃逸、任何已有目标，原有 sentinel 字节与目录清单不变 |
| 双进程同目标 | 真实 spawn 竞争，一方取得目标并导出，另一方冲突；不得混合 payload 或清理赢家数据 |
| 预算边界 | 数量/单文件/总量/manifest 的 0、恰好足够、差一；增长与裁剪不返回成功，读取/内存有界 |
| 变化检测 | 复制中源增删文件/目录、同长度内容修改、末次出现锁或未知落点，均失败且不发布 manifest |
| 输出复核 | 在最终验证前改坏目标字节、缺失或增加条目，必须失败；不能只验证源字节正确 |
| IO/取消/清理 | 发布前取消、读取/短写/close/发布失败；主错误保留，清理失败残留可见，无活动句柄泄漏；发布后迟到取消如实报告已发布 |

时序用已有 hook 或有限的 backup IO 注入边界确定，默认生产行为仍真实 fs；不靠 sleep/目录偶然顺序。能实际创建的 junction 对照要执行；文件 symlink 权限不足时显式 skip，不记空通过。坏 JSON/BOM/非法编码若不能通过现有业务准入，应做拒绝对照，不放宽业务解析器来制造“字节保真”成功。
