## 3. 节点 B：BM-03 真实领域服务

当前 `core/projects` 只有授权与文件名线索 probe，存储已经提供 registry/readRecord/createRecord/updateRecord/updateRegistry。需要新增业务编排，不重写存储、锁、journal 或审核协议，不依赖桌面 main 层。

### B1：显式绑定与档案打开

- 输入必须指定知识根、已授权项目目录及必要的 project/workspace 选择；写操作由人工明确发起。验证在 IO 前，模型参数不能扩大授权根。
- 复用 `resolveProjectBinding` 与既有 ID/路径规则。新项目/工作区用稳定 UUID；同远端、同目录名、同板名都不能自动合并。已有同项目的另一工作区仅在显式选择后绑定。
- 初次创建合法 schema v1 的 ProjectProfile，身份字段未知，不虚构厂商/客户/CRB；打开已有档案时读实际记录并核对 registry/profile 归属。
- 多工作区必须显式选择；路径迁移保持 workspaceId，不可达目录保留绑定并报告 missing/permission-denied，不删除它或选第一个代替。
- registry/profile 是两个文件，**没有通用事务保证**。限定固定步骤，保留每一步是否发布和 revision；故障/CAS 失败/取消后如实报告部分完成，重复执行先读现状再判定。不得无条件删除档案、自动回滚或把半完成报成功。
- 给出只读一致性状态与人工接续方法；仅在状态一致时返回可用于后续业务的完整打开结果。不为了绑定新建通用恢复器。

### B2：有限检测候选与资料缺口

- 保留原 `bios_detect_project` 的只读/授权语义，不偷偷让原工具写档案；本批领域服务和人工入口可以消费 probe 结果。
- 候选与 confirmed 字段分开。至少交付一条真实有界文件读取/解析规则（例如 EDK II DSC 的平台名称/包入口），用脱敏 fixture 证明从文件内容取得结果；不是给测试对象预填候选就声称检测完成。
- 只读取明确支持格式和授权目录内的有限文件；设文件数、逐文件/总字节、输出/候选数量、深度与取消限额。证据保存相对路径、所属 workspace、采集时间和可复核 hash/位置，拒绝根外链接，不把源码正文塞满上下文。
- 解析信号必须有对应字段语义：平台名称不能自动等于客户板名；看到 .inf/.dsc 不能推断 AMI/Intel，更不能推断代际。没有合法规则的身份字段保持 unknown，给出具体所需资料。
- 冲突候选保留来源差异；截断/不可读/取消均可见，不把缺失当“没有冲突”。时间由适配层显式传入或记录实际采集时间，不能拿 updatedAt 猜业务生效期。

### B3：人工确认与 CAS 保存

- 明确有限字段 allowlist、合法值/证据来源、目标 project/workspace、expectedProfileRevision；使用既有 updateRecord，写回合法 v1。
- 人工确认是独立写动作，不是检测后的自动副作用。既有 confirmed 与新候选不同：保留确认值，结果显示候选差异/待复核；用户显式修改确认值后再 CAS 写入。
- 未触达字段、其他工作区、已有证据与资料缺口不能被整份重建覆盖。两个进程确认同 revision 不得最后写者静默覆盖；失败不改变原字节。
- 不往 v1 添加 confirmedBy/history 等未定义字段；operatorLabel 如用于命令输出，只是声明，不声称项目确认已有审核审计。历史字段值查询留待正式 M2。

### B4：工作区快照、证据复验与 M1 消费

- 每 workspace 分别采集 availability、branch/HEAD/capturedAt；Git 目录（含 worktree）、detached HEAD、非 Git 均有对照。非 Git 省略 vcs，不能写空串伪装 Git。
- 若调用 Git，使用固定 argv 而非 shell 字符串，固定已授权 cwd，限时/限输出、支持取消并回收进程/监听器；不得 fetch、执行项目脚本或读认证信息。远端 URL 不必自动采集，未知可以 null；如果显示必须防止凭证泄漏。
- 证据按所属工作区和相对路径重新有界读取/hash 比较。文件变动、缺失、不可读、HEAD/board/build target 变化分别显式显示；不能把其他 worktree 的 HEAD 当本工作区值。
- 刷新采集结果和修改 confirmed 值是不同动作。更新快照复用 CAS；旧证据变为 stale/unavailable 时不自动删除或覆盖人工确认，消费视图保留确认来源并提示待复核。
- 使用修后的 M1 生成结构化、受预算限制的读取视图；不只创建 MemoryCandidate 后丢在 demo 中。区分档案确认值、新检测候选、证据有效性与当前可验证性；v1 无生效区间/依赖快照的经验继续 legacy/reference，不为提升 current 数量补造时态。
- 明确每次读取的知识/profile revision 与所选 workspace 快照，变化后重新判定；不能宣称跨 registry/profile/源码/Git 的读取是原子快照。

API 名称可依实际职责选择，但必须有可复用 typed core 入口和受控结果；CLI 不包含领域规则。模块目标不超过 400 行，超过 600 必须评估拆分；不建单个巨型项目管理器，不引入 any/不安全断言。

## 4. 节点 C：人工入口与一次完整演示

提供一个薄人工 CLI（可独立 `cli/project.mjs`＋npm script，不强塞进备份 CLI），覆盖**绑定→检测→确认→刷新/读取**。命令名以实施记录为准，保留显式根/工作区/写确认/CAS 参数。

- 默认读取；绑定、确认、持久化刷新需人工写入确认。解析失败和失败码有受控 JSON 单对象，未知长参数不无限回显；不默认回退真实知识根。
- Ctrl+C/AbortSignal 传递到文件与 Git 子进程；若已写入必须如实给出发布事实，不“取消＝零变化”。
- 不注册模型知识写工具、不改 Electron/PiRuntime；本批入口是验收/工程师手动消费，不是桌面正式接入。
- 用自建知识根和两个合成工作区演示：初始化/绑定→检测未知及真实候选→工程师确认→新进程读取同 ID/revision/确认值→修改一份证据或切换 Git HEAD→再读提示变化但不覆写确认→切到第二工作区不串快照。
- 演示必须调用真实领域与存储 API/真实 CLI，不输出预写字符串，不读取客户代码。保留运行说明与可复现输出，不将整段临时绝对路径当产品身份。
