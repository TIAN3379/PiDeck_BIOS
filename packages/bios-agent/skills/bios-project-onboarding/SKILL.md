# BIOS 项目接入

目标：得到一份**可复核**的项目档案，而不是一份看起来完整的猜测。

## 基本原则

- 只写有证据的结论。检测不到就保持 `unknown`，并写出缺口——不要用常识补全厂商、芯片代际或板卡。
- 身份字段（IBV、芯片厂商／家族／代际、板卡与版本、客户／产品线、CRB 基线）必须由人工确认。
  模型可以提出候选，但不能把候选写成已确认。
- 不把客户资料、BIOS 镜像或厂商内部文档复制进本仓库；知识只记录引用与相对路径。

## 工作流

1. **只读检测**：调用 `bios_detect_project`（可选 `targetDir`）。
   它返回 BIOS 构建／描述线索文件（`.inf`／`.dec`／`.dsc`／`.fdf`／`.asl`）的计数与样例相对路径，
   外加资料缺口。它不会读文件内容，也不会判定厂商与平台。
2. **核实构建目标**：结合检测到的线索与人工提供的信息，确认构建目标名与平台包。
   多份候选都要保留（冲突候选不合并），由人工裁决。
3. **定位关键入口**：记录客户定制区、板级目录与构建脚本等入口的相对路径，作为后续任务的定位依据。
4. **列缺口**：把检测结果里的缺口逐条翻译成"需要用户提供什么材料"。
   例：没有检测到任何线索文件 → 先确认目标目录是否为源码根，而不是继续扫更大的目录。
5. **引导确认**：把候选字段、证据与缺口一起交给用户确认；确认后写入项目档案，
   确认过的字段不因后续重新检测被自动改写，基线变化时标记待复核。

## 明确不做

- 不做宏求值、不做完整构建闭包解析、不宣称平台兼容性。
- 不因为"文件长得像"就推断厂商适配规则——厂商规则需要真实样例验证后才接入。

## 当前版本的能力边界

本版本（BM-01）只提供 `bios_detect_project` 这一个只读工具。
项目档案的写入、经验检索、任务交接等工具尚未提供，
遇到这些需求时应如实说明能力缺口，而不是用普通文件操作模拟出一个看起来类似的流程。
